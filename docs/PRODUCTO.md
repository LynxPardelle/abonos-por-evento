# Abonos por Evento

Un organizador importa movimientos de sus canales de pago, revisa sugerencias de asignación y obtiene saldos por participante. El cierre deja un historial de movimientos aplicados, pendientes y reversados para el equipo operativo.

## Primera versión

El piloto lleva una moneda por evento. Admite una fuente CSV documentada, registro manual, importaciones, sugerencias y confirmación de un operador. El producto lleva el control de pagos externos. La fuente de verdad es el registro de movimientos confirmados.

Crear un evento y registrar participantes → importar un CSV sintético → revisar coincidencias → confirmar un abono → verificar el saldo → reversar el abono con referencia al original.

## Modelo comercial

Cobro por evento y plan anual para organizadores recurrentes. Medir tiempo de preparación del cierre, movimientos sin asignar y correcciones de saldo.

## Origen

Proyecto de origen propio basado en el problema comercial de evento-asistentes-operadores. Los esquemas, contratos, ejemplos y código de este repositorio son nuevos. Usa participantes y movimientos sintéticos para las pruebas.
